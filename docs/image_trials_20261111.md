# 图片试用账号批次

本次用户授权创建100个账号，初始总额每账号8000积分，脚本和视频仅对这些账号关闭，管理员继续使用全部入口。

## 实现范围

归属为现有Accounts应用服务、HTTP权限边界和Frontend。IdentityStore增加受控运维方法provision_image_trials，调用现有_account、密码哈希、工作空间与初始积分流水；不新增独立扣款系统、不修改Core生成执行器。批次记录放在新增image_trial_accounts表，绑定account_id，切换工作区不能绕过限制。缺少批次记录的历史账号行为不变，管理员优先保留完整权限。

每批使用稳定batch_id，账号、空间、8000初始积分与限制记录在一个SQLite事务中写入。重复执行同一批次不会再次发放，不会覆盖旧账号；名称冲突则整批拒绝。8000是初始总额，不额外叠加普通注册的200积分。公开注册接口不接收试用权限或初始额度字段。

GET /api/auth/me增量返回image_only布尔值。受限账号访问/scripts、/video和/api/scripts、/api/video、/api/storyboards及其子路径得到403 feature_not_enabled；图片与提示词增强继续开放。首页模板不渲染脚本和视频导航，图片操作菜单不提供视频生成、首尾帧和视频素材入口。Worker接口使用原有独立认证，不受浏览器账号限制影响；已受理任务的恢复规则不变。

账号按trial001至trial100命名，每个密码独立随机生成。明文清单只保存到本机Git忽略的交付目录，不写入仓库、网页静态目录或服务日志；服务器账户表只保存PBKDF2哈希。密码只通过SSH传输到受控运维进程。部署时先备份账本，核对原账号、余额和流水未被批次创建改变。

图片现行计费政策不因本次发号变更：8000积分按普通生成40积分/张可生成200张，带参考图或修改按现行报价扣除，实际可用张数取决于操作。没有开通视频、脚本额度，也没有修改管理员凭据。

## 验证与回滚

测试使用临时数据库、Mock及本地浏览器，覆盖精确初始额度、密码哈希、名称冲突原子性、批次重放、账号/空间隔离、后台拒绝以及管理员导航保留。发布前运行完整verify.py。线上逐个核对100个账号的密码哈希、余额、唯一工作区和初始流水，并用真实登录会话抽查页面/接口；不提交付费生成任务。

迁移为新增表，保留旧表及字段。回滚代码时必须先禁用本批次账号并清除其会话，避免旧代码缺少限制后开放脚本/视频；不删除账号、业务记录或积分流水。修复版重新启用前核对批次权限。旧账号不受影响。
